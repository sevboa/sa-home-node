# Архитектура ядра (`sa_home_node`)

Ядро — нода домашнего роя: читает конфиг, загружает плагины, проверяет их
секции конфига и ключи контента, запускает службы как задачи asyncio и
следит за ними. Плагины подключаются через точки входа группы
`sa_home_node.plugins`.

## Модули и связи

- [config](config.md) — TOML-конфиг ноды: `[node]` (id, пути, плагины) и
  прочие секции, выдаваемые плагинам по месту.
- [content](content.md) — хранилище контента по ключам `<плагин>.<имя>`;
  нода создаёт один `ContentStore` на каталог `content_dir`.
- [plugins](plugins.md) — модель плагина, загрузка точек входа, сборка
  `ServiceContext` для каждой службы.
- [swarm](swarm.md) — рой: линки соседей, маршрутизация запросов, события.
- [host](host.md) — слой платформы: платформозависимое поведение ОС (TCP-опции,
  uptime, процессы и сигналы, питание, самоперезапуск, обновление).
- [services](services.md) — `services/`: назначения, таблица служб, супервизор, процессная и встроенная
  службы, аренда синглтонов, пакеты настроек экземпляров и их репликация, вклад в службу `node`.
- [lifecycle](lifecycle.md) — `lifecycle/`: питание и самоперезапуск (`power.py`), обновление (`update.py`),
  бюджет останова и сторож (`shutdown.py`).
- [protocol](protocol.md) — протокол роя v0: транспорт, конверт, типы сообщений,
  обвязка сервера и клиента.
- [monitor](monitor.md) — встроенный плагин мониторинга: датчики температур, SMART, host-метрики, расписание,
  экспорт метрик, фиксапы.
- [fixups](fixups.md) — фиксапы хоста: идемпотентные донастройки машины (sudoers, polkit, юниты, linger,
  пакеты) под назначения и тип ноды; применяет человек командой `fix`, нода их не запускает.
- [backup](backup.md) — бэкап identity и снапшотов БД на напарнике: асимметричное шифрование, история версий,
  маркер публикации, восстановление через ssh-бандл.
- [wake](wake.md) — пробуждение WoL и доведение службы до готовности: `send_wol` в службе `node`, кэш реквизитов,
  `ensure_service_ready`, фиксап `wol-enable`.
- [tasks](tasks.md) — встроенная служба отложенных задач: очередь с `due_at`, прогрев цели заранее, исполнение
  по действию или `timer`, события `task_prewake`/`task_result`.
- [cli](cli.md) — команда `sa-home-node`.

## Порядок старта и останова (`run_node`)

Подробно с причинами — [lifecycle](lifecycle.md). Кратко:

1. конфиг, плагины, таблица служб, `ContentStore`, `Swarm`; `node_actions` плагинов — в службу роя;
2. `make_context` для каждого плагина (все проверки до запуска первой службы), `mkdir` каталогов данных;
3. обработчики сигналов хоста — до `swarm.start()`;
4. супервизор по действующим назначениям: служба с `process=True` — отдельный процесс, остальные — задача в
   ноде; запускаются только назначенные (в т.ч. `monitor`, `tasks`, бэкап-плагины);
5. хранилище пакетов, репликатор, аренда, вклады `supervisor`, `power`, `update` в службу `node`;
   бэкап: `IdentityPublisher`, `SnapshotBackup` (источник/приёмник снапшотов) при заданном `partner`;
   wake: кэш реквизитов соседей, действие `send_wol` в службе `node`;
6. `swarm.start()`, локальные цели роутера, `replicator.start()`, `supervisor.start_all()`, `lease.start()`;
   tasks: `TaskRunner` (циклы прогрева и срабатывания) стартует внутри службы `tasks`;
7. останов под `ShutdownBudget`: прощание `node_leaving`, аренда, репликация, службы, линки, рой; сторож
   `arm_hard_exit` страхует зависший останов.

Сборка ноды — `node.py` (`run_node` — нода, `run_service` — вход процессной службы); `services/actions.py`,
`lifecycle/power.py` и `lifecycle/update.py` добавляют действия и состояние в службу `node` роя.

Политику перезапуска упавшей службы (`restart_delay_s`, `stop_timeout_s` из `[node]`) держит слот
(`ProcessService` или `InProcessService`), служба сигналов не знает: встроенную останавливает отмена задачи,
процессную — сигнал хоста.

## Быстрый старт

```toml
# config.toml
[node]
id = "имя-ноды"
plugins = ["example"]

[example]
interval_s = 5
```

```toml
# content/example.toml
greeting = "Привет!"
```

```bash
sa-home-node run --config config.toml   # остановка: Ctrl+C
```

Плагин `example` раз в `interval_s` пишет приветствие из контента в журнал.
