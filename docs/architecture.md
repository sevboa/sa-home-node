# Архитектура ядра (`sa_home_node`)

Ядро — нода домашнего роя: читает конфиг, загружает плагины, проверяет их
секции конфига и ключи контента, запускает службы как задачи asyncio и
следит за ними. Плагины подключаются через точки входа группы
`sa_home_node.plugins`.

## Модули и связи

- [config](config.md) — TOML-конфиг ноды: `[node]` (id, пути, плагины) и
  прочие секции, выдаваемые плагинам по месту.
- [content](content.md) — хранилище контента по ключам `<плагин>.<имя>`;
  нода создаёт один `ContentStore` на каталог `content_dir`.
- [plugins](plugins.md) — модель плагина, загрузка точек входа, сборка
  `ServiceContext` для каждой службы.
- [swarm](swarm.md) — рой: линки соседей, маршрутизация запросов, события.
- [host](host.md) — слой платформы: платформозависимое поведение ОС (TCP-опции,
  uptime, доступность unix-сокетов).
- [protocol](protocol.md) — протокол роя v0: транспорт, конверт, типы сообщений,
  обвязка сервера и клиента.
- [cli](cli.md) — команда `sa-home-node`.

## Порядок старта (`run_node`)

1. `load_config(path)` — конфиг ноды;
2. `load_plugins(cfg.node.plugins)` — плагины по именам из конфига;
3. `ContentStore(cfg.content_dir)` — одно хранилище контента;
4. `Swarm(cfg, NodeState.load(...))` — рой ноды; действия
   `node_actions` плагинов регистрируются в службе роя (`actions.add`)
   до запуска служб, чтобы другие ноды сразу видели их в `describe`;
5. `make_context` для каждого плагина — все проверки секций и ключей
   контента проходят до запуска первой службы; любая ошибка (`ConfigError`,
   `ContentError`, `PluginError`) падает до старта служб; контексту службы
   передаётся `SwarmApi`;
6. `mkdir` каталога данных каждого плагина (`data_dir / <имя плагина>`);
7. `swarm.start()` — ДО запуска служб: иначе первое событие службы
   уходит в незапущенный рой и соседям не доедет;
8. по задаче `asyncio` на каждую службу — супервизор `supervise`.

## Супервизор и политика перезапуска

`supervise(name, spec, ctx, restart_delay_s)` в цикле:

- обычный возврат `spec.run(ctx)` — запись в журнал и выход из цикла;
- исключение (кроме `asyncio.CancelledError`) — запись в журнал с именем
  службы, пауза `restart_delay_s` (по умолчанию `RESTART_DELAY_S = 5.0`)
  и новый запуск.

Служба не знает о сигналах: остановка — только отмена задачи.

## Остановка

Если `stop` не передан, `run_node` создаёт `asyncio.Event` и вешает
`loop.add_signal_handler` на SIGTERM и SIGINT (снимает в `finally`).
По `stop.wait()` задачи отменяются в обратном порядке запуска, каждая
дожидается отмены; затем `swarm.stop()` — он шлёт событие `node_leaving`
о себе, чтобы соседи сразу пометили штатный уход.

## Быстрый старт

```toml
# config.toml
[node]
id = "имя-ноды"
plugins = ["example"]

[example]
interval_s = 5
```

```toml
# content/example.toml
greeting = "Привет!"
```

```bash
sa-home-node run --config config.toml   # остановка: Ctrl+C
```

Плагин `example` раз в `interval_s` пишет приветствие из контента в журнал.
