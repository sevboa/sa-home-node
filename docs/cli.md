# Команда `sa-home-node` (`sa_home_node.cli`)

Точка входа `sa_home_node.cli:main` (`[project.scripts]` в
`pyproject.toml`). `main(argv=None) -> int` — код выхода.

## Подкоманды

- `run [--config PATH]` — запуск ноды (`run_node` из `sa_home_node.node`
  через `asyncio.run`); перед запуском `logging.basicConfig(level=INFO)`. Если `run_node` вернул `True`
  (самоперезапуск), вызывается `host.current().self_restart(sys.argv)`.
  `ConfigError`, `ContentError`, `PluginError` печатаются в stderr строкой
  `ошибка: <текст>`, код 2; остальные исключения не ловятся.
- `service NAME [--instance I] [--config PATH]` — вход процессной службы (`run_service`); его запускает сам
  супервизор ноды, вручную нужен для отладки. Код выхода: 0 — штатно, 11 — служба вытеснена (`ServiceFenced`),
  2 — ошибка конфига, контента или плагина. Подробнее — [services](services.md).
- `fix [--config PATH] [--list] [--dry-run] [--only ID[,ID]]` — фиксапы хоста ([fixups](fixups.md)): загружает
  конфиг и плагины (рой и службы не поднимаются), собирает фиксапы для действующих назначений и типа ноды, печатает
  заголовок «Нужно проверить N фикс(ов) под назначения [...]:» и запускает их. Флаги:
  - `--list` — по строке `<id><TAB><title>` на каждый фиксап списка, без проверок, код 0;
  - `--dry-run` — только проверки: отрицательные печатаются как «нужно применить», `apply` не зовётся;
  - `--only` — только перечисленные id через запятую; неизвестный id — ошибка со списком доступных.

  Коды выхода: 0 — всё применено или уже применено; 1 — есть сбои (строка «Не применилось: a, b — см. вывод
  выше.»); 2 — ошибка конфига или плагинов (`ошибка: <текст>` в stderr; ничего не применяется); 3 — только с
  `--dry-run`: остались неприменённые. Нужных фиксапов нет — «Все известные фиксы либо не нужны для текущих
  назначений, либо уже применены.», код 0. После успешного применения печатается напоминание перезапустить затронутые
  службы. `sudo` запрашивается интерактивно, поэтому `fix` запускают из терминала.
- `plugins` — имена из `plugins.available()` по одному в строке; если
  плагинов нет — строка `плагины не установлены`; код 0.
- `ctl` — консоль управления нодой ([ctl](ctl.md#sa-home-node-ctl--консоль-управления)).
- `init` — мастер инициализации ([ctl](ctl.md#sa-home-node-init--мастер-инициализации)).
- `backup [--config PATH] keygen|list|restore|stage|apply|release` — бэкап и восстановление службы ноды из копии
  напарника ([backup](backup.md)). Конфиг нужен во всех подкомандах, кроме `keygen`.
  - `keygen [--out ПУТЬ]` — сгенерировать пару ключей получателя: приватный пишется в файл 0600 (по умолчанию
    `~/.config/sa-home-bot/backup.key`, существующий не затирается), публичный печатается для `[backup].recipient_public_key`.
  - `list НОДА [--holder]` — какие копии (identity и снапшоты) есть у хранителя, с метками и признаком пустого снапшота.
    `--holder` — задать ноду-хранитель явно (по умолчанию — первый живой пир с копией).
  - `restore НОДА (--dry-run КАТАЛОГ | --apply) [--snapshot last_nonempty|latest|МЕТКА] [--identity МЕТКА]
    [--no-snapshot] [--holder] [--ssh-host] [--remote-nodectl] [--wipe-db] [--yes]` — собрать бандл восстановления
    у хранителя, расшифровать приватным ключом; `--dry-run` раскладывает бандл в каталог (0700/0600) и не трогает ноды,
    `--apply` доставляет по ssh и запускает `nodectl backup apply` на цели (интерактивный `sudo`, tty). Пустой `latest`
    при наличии `last_nonempty` — отказ (подсказка выбрать явно). `--wipe-db` — очистить таблицы снапшота перед заливкой.
  - `stage` — принять бандл со stdin (0600) в `restore-bundle.json` рядом с состоянием.
  - `apply [--bundle ПУТЬ] [--yes] [--wipe-db]` — применить бандл локально (показывает сводку, спрашивает подтверждение,
    если нет `--yes`; интерактивный `sudo`).
  - `release` — разрешить этой ноде публиковать бэкап напарнику (ставит маркер `backup-publish.ok`).

  Коды возврата: 0 — успех, 1 — ошибка выполнения, 2 — ошибка конфига или плагинов.
- без подкоманды — справка (`parser.print_help()`) и код 2.

## Пример

```bash
sa-home-node run --config config.toml
sa-home-node plugins
sa-home-node fix --dry-run
sa-home-node fix --only node-linger
```
