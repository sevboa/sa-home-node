# Жизненный цикл ноды

## Питание и перезапуск

Модуль `sa_home_node/lifecycle/power.py`, точка входа `register_power(node_service, *, kind,
power_controllable, request_restart, router, blockers)` (необязательные `run` и `sleep` подменяют запуск
процесса и ожидание в тестах).

Действия службы `node`:

- `restart_node` — объявляется всегда; `request_restart` — колбэк самоперезапуска.
- `poweroff`, `reboot`, `suspend` — только если `power_controllable` истинно; при `None` решает тип ноды
  (`traits_for(kind).power_controllable`, у постоянно включённых типов питание не объявляется). Команда берётся
  из `host.current().power_argv`, платформенных проверок в модуле нет.

Питание и перезапуск выполняются с задержкой `POWER_DELAY_S` = 1 с, ответ `{"scheduled": действие, "delay_s": 1.0}`
уходит раньше самой команды: иначе вызывающий не получил бы ответ. Ссылки на задачи хранятся в множестве,
иначе сборщик мусора может убить отложенную задачу. Ненулевой код команды пишется в журнал.

### Выключение «если простаивает»

`poweroff` с `if_idle: true` (строго булево `true`) выключает, только когда блокеров нет. Ответ
`{done, blockers}`. Порядок блокеров: `службы: …` (`router.busy_services()`), SSH-сессии
(`пользователь, tty, с метка_времени` из `loginctl`, только удалённые), `tmux: имя`, затем поставщики
плагинов (`Plugin.power_blockers`). Отсутствие `loginctl` или `tmux` — не блокер. Сбой поставщика
плагина не глотается: выключение не выполняется, ошибка идёт вызывающему.

### Отложенный `restart_node`

Занятость — `router.working_services()` (службы, которые заняты работой, а не просто держат соединение).
Если заняты, перезапуск откладывается: ответ `{deferred, max_wait_s, message}`, где `deferred` — занятые
службы. Ожидание опрашивает каждые 30 с и перезапускает ноду, когда все свободны или прошло 1800 с.
Повторный вызов во время ожидания ничего не запускает и отвечает `deferred: []`, «ожидание рестарта уже
идёт». `force: true` отменяет ожидание и перезапускает сразу. Сбой опроса занятости при вызове считается
«не занято», в ожидании — приводит к принудительному перезапуску: нода не должна зависнуть из-за сломанного
опроса.

## Обновление

Модуль `sa_home_node/lifecycle/update.py`, точка входа `register_update(node_service, *, repo, emit, run)`.
`repo` — адрес репозитория, из которого поставлено ядро (`origin_repo_url()`: git-установка не в режиме
разработки); при `None` ничего не объявляется. `emit` — отправитель событий, `run` подменяет запуск процесса
(принимает `timeout` и `env`, по умолчанию `run_command`).

- `check_update` — `{repo, running, installed, latest}`: `running` — версия работающего процесса,
  `installed` — версия на диске, `latest` — старший тег `vX.Y.Z` из `git ls-remote --tags --refs` без `v`.
  Теги сравниваются по числовым компонентам, не по строке. Нет сети или тегов — ошибка `internal`
  «не удалось проверить обновления (сеть?)».
- `update` — если версия на диске уже равна последней, ответ `{up_to_date, version, restart_required}`, где
  `restart_required` — «работающая версия отличается»: обновление могло быть поставлено раньше, а нода ещё
  не перезапущена. Иначе установка идёт фоновой задачей, ответ `{scheduled, target_version}`; второй вызов
  во время установки — `bad_request` «обновление уже выполняется». Сама нода не перезапускается: это
  отдельное действие `restart_node`.
- Linux: `pipx install --force "<пакет>[<экстры>] @ git+<repo>@<тег>"`. `PIPX_HOME` берётся от работающего
  интерпретатора (`parents[3]`), чтобы переустановка попала в то же окружение; экстры — из
  `pipx_metadata.json` этого окружения, иначе они пропали бы после обновления. Таймауты: опрос тегов
  `DEFAULT_TIMEOUT - 3`, установка 300 с; хвост вывода — 2000 символов.
- Windows (`host.current().update_via_task`): запускается задача автообновления, ответ дополнен
  `"via": "scheduled_task"`. Задача перезапускает службу сама, поэтому событие `update_finished` приходит
  только при ошибке запуска задачи.
- Событие `update_finished {ok, version, error}` после установки; то же значение лежит в `last`.
- Вклад `update` в `get_state`: `{running, installed, restart_required, last}`; `restart_required` истинно,
  когда версия на диске известна и отличается от работающей.
